# Сайт BillPay Protocol: требования

Сайт — **первый проект сообщества**. Публичный, сеть Base.

## Пользователи
Посетитель · Заявитель · Покупатель лота (валидатор) · Член совета · Основатель

## Страницы
1. **Главная / Панель**: Счётчик Влияния (баланс `solidarityWallet` в реальном времени), всего выплачено, число семей, получивших помощь, следующее распределение (обратный отсчёт 24 ч).
2. **Раздел заявителей**: подключение кошелька, форма (сумма, поставщик, срочность, описание без вставки), загрузка счёта со скрытием личных данных.
3. **Трибунал солидарности**: анонимные карточки, ДА/НЕТ (вход через Google или аналог), статус (валидации 0/5, одобрения совета, задержка 24 ч).
4. **Раздел валидаторов**: только для покупателей лотов, ончейн-валидация.
5. **Совет**: состав месяца, рейтинги (инфлюенсер, X, Facebook, TikTok, трейдер, топ-кошелёк), голосование за выборное место.
6. **Лоты**: серии, цена, оставшееся количество, покупка лота (1 на кошелёк), график вестинга (клифф 45 дн., линейно 30 дн.), `claim`.
7. **Прозрачность**: история выплат, журнал проекта, ссылки на контракты и код.

## Функциональные требования
- Подключение кошелька (Base) и вход через Google для голосования.
- ИИ-проверка заявок (помечает, не платит) до публикации.
- Личные данные никогда не публикуются и не попадают в сеть: публикуется только отпечаток досье.
- Поле описания без вставки (барьер на стороне браузера).
- Уведомления о статусе заявки.
- Сначала французский; затем английский и турецкий (в примере упоминались Euro/Lira).

## Нефункциональные требования
- Mobile first, читаемость, высокая наглядность.
- Шифрование счетов при хранении, ограниченный срок хранения, соответствие GDPR (удаление по запросу).
- Защита от ботов, ограничение частоты запросов, журнал аудита.
- Никаких приватных ключей на стороне сервера.

## Предлагаемый стек
Next.js + TypeScript, wagmi/viem (Base), Google Auth (OAuth), зашифрованное хранилище счетов, база PostgreSQL для голосов, индексация событий контрактов.

## Этапы
1. Макет (`site/index.html`) утверждён.
2. Чтение из сети (счётчик влияния, лоты).
3. Раздел заявителей и Трибунал.
4. Раздел валидаторов и Совет.
5. Аудит безопасности, затем открытие.

## Названия
- Интерфейс: **BillPay Hub** (DApp для голосования: **BillPay DAO**).
- Хостинг: GitHub Pages, `https://trevio-TRVO.github.io/billpay-protocol/` (репозиторий называется `billpay-protocol`).
